# TriPRD 方法方向与 COD 可比性审计

2026-10-22，Asia/Singapore。主要证据为用户指定的 `results/optimization/correction_stratified_probe_v1` 两份真实服务器报告；同时检查当前模型、训练、评测代码以及 COD 方法官方材料。本次新增分析和数据摘要，没有训练新模型、修改旧实验或产生新的 COD 成绩。

**建议停止把“降低教师关系差值的 MSE”作为主线成功标准。优先建立可适配、具有真实细节特征的强 COD RGB 主体，再检验多模态知识是否改善学生实际的对象分割。区域平衡值得保留为诊断控制，但最新结果不足以支持直接推进这个版本的全量跑榜。**

## 1. 最新实验究竟证明了什么

两组均为真实 DINOv3 ViT-B/16、384 输入、batch 8、冻结主干，VDT TRAIN 838 / VAL 210，固定训练 10 轮；每组报告 1,050 次有效优化更新、0 次 AMP 跳步。两组初始化、划分、教师及学习率历史相同，仅区域归约方式不同。`cod_access=false`、`formal=false`，**没有 COD 训练或评测结果**。

下表为同一第 10 轮 checkpoint、VDT VAL、正可靠边上的结果，全部越低越好。零修正和常数修正使用两组共享的参照，常数在 TRAIN 拟合。

| 指标 | pooled | stratified | 零修正 | TRAIN 常数 |
|---|---:|---:|---:|---:|
| 全部区域 MSE | 0.003302 | 0.004340 | — | 0.003856 |
| 前景内部 MSE | 0.018590 | 0.024037 | — | 0.021622 |
| 背景内部 MSE | 0.002649 | 0.003785 | — | 0.003265 |
| 跨边界 MSE | 0.052487 | 0.037509 | 0.037961 | 0.043273 |
| stratified 的 stride-8 跨边界 MSE | — | 0.032489 | 0.030197 | — |
| stratified 的 stride-16 跨边界 MSE | — | 0.047489 | 0.053395 | — |

区域平衡确实减轻了背景主导：VAL 正可靠边中背景占 97.8834%，前景占 1.1843%，跨边界占 0.9323%。但跨边界 MSE 仅比零修正低 **1.192%**，总体 MSE 比常数高 **12.544%**。细尺度仍劣于零修正，相对零修正的聚合优势来自粗尺度；相对 pooled，两个尺度都有改善。TRAIN 跨边界也只比零修正低 **1.421%**，因此当前不像单纯“训练学好了、验证泛化不了”；10 轮预算又不足以证明模型容量的绝对上限。

更有区分力的是实际关系质量。以下均在相同的 VAL 正可靠跨边界子集计算 BCE：

| 操作 | pooled 学生 | stratified 学生 |
|---|---:|---:|
| 学生基础关系 | 0.778157 | 0.831276 |
| 加学生预测修正 | 0.891698 | 0.806289 |
| 加真实教师修正（仅诊断） | 0.588434 | 0.634136 |

这表明：源域这个子集上存在有益信号，stratified 学生只实现了真实教师修正所带来关系 BCE 改善的约 **12.7%**。不能把这个比例当成分割精度或理论上界，也不能据此断言 COD 上同样有收益。

因此，“教师和学生基础概率不兼容”应保留为设计风险，**不能认定为本轮失败的已证实主因**。至少上述子集的反事实证据表明真实差值适用于学生基础关系。更直接的问题是 RGB 学生没有充分学到有用的细尺度修正。

还有一个指标解释陷阱：`source_recoverability.corrected_task_error` 是 **教师 RGB 基础关系 + 学生修正** 的误差，不是部署时的学生关系误差。真正的 `student_task_error` 为 pooled 0.467746、stratified 0.468839，并未整体改善；见 `models/triprd_correction_loss.py:379` 起。不能将前一个很小的数解释成学生任务已经解决。

原始来源及 SHA256、同源性检查、TRAIN/VAL 和两尺度分解见 [数据审计摘要](correction_stratified_audit_2026-10-22.json)。本地只有两份 `comparison.json`，没有对应权重、独立日志和根 manifest；可核验内嵌结果与合约，不能声称已经独立重跑或检查 checkpoint 张量。

## 2. 大方向的四个瓶颈

### 2.1 学到的东西与 COD 要解决的问题不够接近

当前关系标签是相邻像素是否同标签，`y_i == y_j`，见 `models/triprd_correction_loss.py:59`。整幅图交换前景与背景后关系完全不变。它适合辅助区域一致性，却不能独立回答哪个区域是目标。

T/D 信息只进入 stride 8/16 的 3×3 局部边权，传播的 value 和解码器特征仍来自 RGB；见 `models/triprd_correction.py:391`、`:439`。DINO 本身有全局上下文，因此不能说整个模型没有全局信息；问题是**跨模态增量的入口过窄，主要影响局部平滑，而 COD 的定位、对象完整性和细边界仍依赖 RGB 主体**。

归一化邻域传播在局部 value 相近时，对边权改变天然不敏感（同文件 `:261`）。背景边上更低的 MSE 很可能无法转化成输出收益。这是结构推断，不是已经完成的因果验证。

此前 path 诊断的文字记录中，关闭全部传播导致 macro Sm 下降 0.012780，仅关闭修正下降 0.000007（`tools/TRIPRD_STRATIFIED_PROBE.md:3`）。这是较早 COD screen 的记录，不是本次源探针的 COD 结果；它支持继续区分“传播有用”和“三模态修正有用”。本地未取得该诊断原始报告，证据等级低于本次两份原始 JSON。

### 2.2 当前强主干没有得到充分的 COD 适配，细节支路也不是真正的高分辨率输入

`tools/run_triprd_correction.py:290` 起构造模型时固定冻结 DINO。四个中间层来自同一个 patch-16 网格，384 输入对应 24×24；`_PyramidAdapters` 再插值成 stride 4/8/16/32（`models/triprd_correction.py:195`、`:223`）。

这提供了不同深度的语义表征，但上采样不能新增未被编码的图像细节。当前所谓 adapter 位于主干输出后，不能改变 Transformer 内部的 COD 表征。细尺度 crossing 的 TRAIN 和 VAL 都弱，与这一限制相容，但不构成单独归因证明。

优先验证两个独立因素：**主干内部可训练适配 / 后部 block 微调**，以及**直接从 RGB 提取的 stride 4/8 细节特征**。不要把“换成 DINOv3”本身当成已经建立强基线，更不能把新主体的收益归给蒸馏。

### 2.3 优化了教师自己的残差，却没有直接保证学生最终任务改善

教师目标为 `q_RTD^T - q_R^T`，学生使用 `q_base^S + delta^S`。这不是同一个基准；而学生 base 和 corrected 又分别被 GT 监督成相同关系，允许基础路径吸收任务信息，使修正成为冗余路径。见 `models/triprd_correction_loss.py:148`、`:198` 和 `models/triprd_correction.py:361`。

最新数据已说明：MSE、把学生修正放到教师 base 上的 BCE、学生真实关系 BCE、最终 COD 指标是四个不同层次。以第一个作为阶段通行证，会不断投入资源解决代理任务。

下一版应把主监督落到**学生实际用于解码的表征或修正后的任务输出**。教师 RGB/多模态差异可以作为训练时选择可靠区域的证据，但不要求学生复现教师自身校准下的数值差。绝对目标 KD 是必要控制，这类改动本身不是原创性证明。

### 2.4 SOD 到 COD 的任务冲突仍被共享解码器承担

源、目标只分开最后输出头，adapters、关系模块和 decoder 共用（`models/triprd_correction.py:348`）。每个 COD batch 搭配一个循环 VDT batch，源监督持续进入共享参数；E/F 的梯度选择仅作用于 KD，源 RGB/GT 监督不受控制，而且 alignment 只检查 adapters（`tools/run_triprd_correction.py:437`、`:488`）。

历史 v2 已出现所有源训练组 CAMO Sm 上升、COD10K Sm 下降；三模态 E 对 A 的宏 Sm 仅 +0.000123。这不能证明任务冲突的具体机制，却足以否定“源损失更好自然意味着 COD 更好”的默认假设。参见 [v2 原始分析](structure_v2_analysis_2026-10-19.md)。

重设计时允许源/目标拥有不同的任务 adapter 或 decoder，保留有限的共享结构表征；源监督的进入位置和日程作为受控设计。不能仅靠对 KD 做一个 batch gate 就宣称解决了源任务负迁移。

## 3. 推荐的下一版：两步推进

### 第一步：先建立能独立竞争的 RGB COD 主体

保留当前冻结主体为控制，以同一通用预训练、384 输入、固定内部划分和 COD 预算测试：

| 新实验代号 | 改动 | 回答的问题 |
|---|---|---|
| R0 | 当前主体，仅 COD | 当前独立性能基点 |
| R1 | R0 + 主干内部适配，或后部 block 小学习率微调（二选一先做） | 是否主要受任务适配限制 |
| R2 | R0 + 真实 RGB stride 4/8 细节支路 | 是否主要受细节表示限制 |
| R3 | 合并已经有效的因素，粗到细输出监督 | 改善能否叠加 |

这些代号不重用旧 A/B/C/D，避免混淆历史结果。用普通的多层特征解码和已有 weighted BCE + weighted IoU 先建立性能，不同时堆叠频域、扩散、MoE 等模块。裁剪/尺度增强值得单独检查，但同一轮方法消融必须使用相同增强；先维持分辨率不变以免混淆。

先依据训练收敛和内部验证冻结一种主体，再进入多模态。若主体已改变，应重新训练所有配对控制，旧 A/B 不能直接复用。

### 第二步：只验证一种更贴近任务的多模态迁移

建议优先方向为**任务表征蒸馏**：教师在真实源 RGB/T/D 上输出由源标注约束的对象区域与边界表征；RGB 学生的对应表征进入粗定位或细化特征路径，直接受分割监督。辅助信息可以进入教师的融合特征，不再硬性限制成局部 scalar 边权；学生部署仍只输入 RGB。

首个实现保持小而明确：一个参与解码的结构特征分支，教师端/学生端各一个投影，源域在 GT 支持的区域比较任务表征或任务输出，COD 用自己的 GT 优化整个 RGB 预测路径。教师相对 RGB 的改善仅用于可靠性控制。不要同时引入对象原型、距离场和多个新损失；这些是后续候选，不应一轮全上。

这一方向仍需实验，不保证比现有方案强。过去直接 logit KD 已有负结果，简单改回 logit KD 或恢复整网源预训练不能算新方案。真正需要验证的是：**可学习的任务表征是否进入学生的分割路径，并在强 COD 主体上带来独立多模态收益**。

建议按依赖关系运行下列控制，均从同一通用预训练和同一学生初始化开始：

| 控制 | 数据与教师 | 作用 |
|---|---|---|
| T0 | 仅 COD RGB/GT | 强主体基线 |
| T1 | 增加 VDT RGB/GT | 分离额外样本和源任务监督 |
| T2 | T1 + 容量匹配 RGB 教师，使用拟议迁移目标 | 分离教师容量与蒸馏本身 |
| T3 | T1 + RGB/T/D 教师，普通任务输出或特征 KD | 比较简单多模态蒸馏 |
| T4 | T1 + 同一 RGB/T/D 教师，拟议任务表征迁移 | 检验目标设计的额外收益 |

先 T0/T1，再运行依赖教师的 T2–T4；只有 T4 同时超过这些关键控制，才补错配模态、单独 T/D 等机制消融。教师容量和训练更新次数匹配；学生结构、可训练容量、COD 更新和源样本暴露匹配。若 T3 与 T4 只有可靠性权重不同，应如实将结论限定为该权重的作用。

进入最终实验的依据是同一 checkpoint 的内部 COD Sm/Fw、逐来源表现、误差类型以及跨 seed 重复。至少用 3 个配对种子核查保留方案与强控制，报告均值和标准差；逐图 bootstrap 不能替代训练随机性。持续出现 COD10K 退步、总体无收益时停止扩展该迁移机制，而不是换宏平均权重。

源探针仅做预算有限的筛查：同时检查零/常数参照、真实学生任务误差和两个尺度；通过不自动放行全量训练。若理想源教师信号无法被学生学到，先改善可学习性；若学到了却不提升 COD，转向任务迁移问题。可在内部验证进行 GT 辅助的关系替换诊断，但它有标签且可能分布外，只能诊断路径，不能进入正式成绩或当成严格性能上界。

## 4. 与 COD 公认方法保持可比的协议

共同基准不意味着所有方法必须使用同一个优化器、学习率或 epoch。CamoFormer 论文使用 384、60 epochs、SGD；ZoomNeXt 官方配置使用 384、150 epochs、Adam。二者都采用 3040 COD10K + 1000 CAMO 训练池。应统一数据、任务、评测定义，并披露各自训练资源；我们自己的消融则严格匹配预算。[CamoFormer §4.1](https://arxiv.org/html/2212.06570v1#S4.SS1)、[ZoomNeXt 官方配置](https://github.com/lartpang/ZoomNeXt/blob/main/configs/icod_train.py)

| 项目 | 本项目应固定的约定 |
|---|---|
| COD 最终训练池 | COD10K 的 3040 张伪装训练图 + CAMO 的 1000 张训练图，共 4040；不混入 COD10K 非伪装/背景测试样本 |
| 方法开发 | 只在官方训练池内部划分；当前 3232 TRAIN / 808 VAL 可继续，但这是项目内部协议，不是论文官方测试 |
| 最终重训 | 方案和预算冻结后从通用初始化开始，用 full4040 重训；采用预先规定的最后 epoch，或预先规定的另一种不访问测试集的选模规则；本项目现有固定末轮可保留 |
| 测试集 | COD10K 2026、CAMO 250、CHAMELEON 76、NC4K 4121；逐数据集完整报告 |
| 指标 | S-measure、weighted F-measure、MAE，以及明确标注的 adaptive / mean / max E；CamoFormer 的 αE 表对应 adaptive E |
| 输出 | 连续概率灰度图，原始 GT 尺寸；固定插值、sigmoid、归一化及量化顺序，保存原始预测 PNG |
| 推理 | 所有最终测试使用同一选定权重；RGB-only；单尺度主结果，TTA/多尺度/后处理若启用须另列并披露 |
| 禁止选模方式 | 不按测试数据集分别挑 epoch、不拼单指标最优、不用正式测试挑损失/阈值/主干 |
| 数据与计算资源 | 披露 DINOv3 LVD-1689M 通用预训练、VDT RGB/GT、VDT T/D 教师、输入尺寸、总/可训练参数、训练成本和推理成本 |

VDT 的使用属于额外数据/特权监督设置。可以在同一官方测试集比较绝对分数，但不能声称与只用 COD + ImageNet 的方法资源等价。主表明确资源列或分组，并提供同主干、同额外 RGB 数据的控制。保持既定不使用 VDT test、不引入伪 T/D 或合成 COD 的数据边界。

### 已正确的实现

当前评测类来自 CamoFormer，并已分开 mean/adaptive/max E；训练最终入口已有 full4040 与四测试覆盖检查，内部选模使用同一 checkpoint 的宏 Sm，探针/MSE screen 不访问正式测试。这些应保留。本次在本地 `dataset-py311` 环境复跑 `tests.test_camoformer_evaluation` 和 `tests.test_validation_metrics`，10 项测试通过；这是指标回归检查，不能代替上述完整性与推理流程修订。

### 正式跑榜前的三项必要修订

1. **版本化预测导出。** `tools/run_triprd_ab.py:316` 当前为 `sigmoid → uint8 截断 → PIL resize`，correction 验证和测试也复用它。CamoFormer 先将 logits 插值到原图，再 sigmoid、round 后存 PNG。两者不等价，尤其可能影响边界。这不表示现有分数自动无效，也不保证修改后涨分。下一版明确采用一种官方参考流程并记录版本；开发验证、最终导出保持一致，同一权重可双流程复评但不能根据测试涨跌挑流程。[CamoFormer decoder](https://github.com/HVision-NKU/CamoFormer/blob/main/model/decoder/decoder_p.py)、[test.py](https://github.com/HVision-NKU/CamoFormer/blob/main/test.py)
2. **独立 evaluator 默认检查完整一一对应。** `tools/evaluate_cod.py:169` 起按现有预测目录遍历，独立 CLI 缺图也能得到正常分数，同 stem 的不同扩展名还可能重复计入。外层完整评测的保护不能替代此入口的保护。必须检查官方 GT ID 集合 = 预测 ID 集合、唯一性、可解码性和计数；部分评测显式标记，禁止进入主表。
3. **主表导出默认只接受冻结 benchmark 协议。** `tools/summarize_triprd_correction.py:98` 仅在模式已经是 full 时校验 4040；split 模式可绕过。`run_triprd_correction.py:811` 的 `formal` 也不等于“具备主表资格”。新增明确的 benchmark 状态；主表出口要求 full4040、非 tiny、完整测试、权重 hash、固定选模和评测版本。开发测试如需导出，应独立出口并标为 development。

上述修改应在新实验版本中完成，不能静默改变已有源码哈希约束下的历史记录。若只改预测导出，可对同一固定 checkpoint 复评；若改模型、增强或选模标准，必须重新建立匹配的开发对照。

对于外部方法，优先取得官方预测图，用同一指标实现复评；只有论文数字时标记为引用结果，E 类型不明则暂不混入该列。不同方法的官方前向/后处理可能不同，应披露，不应为了形式一致擅自修改其方法后仍称官方结果。

## 5. 更新比较对象，避免对旧表宣布 SOTA

`previous_performance.tex` 的主要方法截止到 2025，且标题是另一项 E2Net 工作；它是参考材料，不是截至 2026-10-22 的完整基准。保留本项目独立于 E2Net 的边界，不复用它的模块或 COD 权重。

经典协议锚点可用 CamoFormer、ZoomNeXt；新的相关对照至少核查 ESCNet（ICCV 2025）和 DepthSAM（CVPR 2026）。DepthSAM 已明确指出直接深度迁移与 COD 存在任务错位，并采用任务适配及几何语义融合。它同时使用 SAM/深度模型资源，不能只拿分数而忽略成本。[ESCNet 官方论文](https://openaccess.thecvf.com/content/ICCV2025/html/Ye_ESCNetEdge-Semantic_Collaborative_Network_for_Camouflaged_Object_Detection_ICCV_2025_paper.html)、[DepthSAM 官方论文](https://openaccess.thecvf.com/content/CVPR2026/html/Han_Beyond_Appearance_Camouflaged_Object_Detection_via_Geometric_Structure_CVPR_2026_paper.html)、[官方代码](https://github.com/hjy0518/DepthSAM)

本次没有完成整个领域的穷尽排名核验，也没有可比的最新 TriPRD 四测试集成绩，不能给出“距离 SOTA 差多少”或承诺某个修改必然达到 SOTA。下一阶段可检验的目标应是：强主体可复现、资源透明、多模态增量相对强控制稳定成立；再用冻结方案的官方测试成绩判断竞争力。
